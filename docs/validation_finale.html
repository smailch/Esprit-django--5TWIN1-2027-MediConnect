2 · Tests & besoins non fonctionnels 4 points

Stratégie de tests

  • Unitaires : modèles, règles métier, garde-fous IA (IA simulée), formulaires, gabarits
  • Intégration (tests_integration.py, vraie base + client HTTP) : CRUD de chaque entité, inscriptions, parcours complets, statuts HTTP
  • Permissions testées : matrice 5 rôles × 21 adresses (anonyme → connexion, autre rôle → 403), données d'un autre compte → 404
  • Couverture : coverage run manage.py test → 89 %, rapport HTML publié par la CI

Sécurité (OWASP)

  • CSRF sur tout formulaire (page claire si le jeton expire), ORM uniquement
  • Mots de passe hachés PBKDF2 + validateurs ; blocage 15 min après 5 échecs
  • DEBUG=False imposé en production, clé forte obligatoire, HTTPS, HSTS, cookies Secure/HttpOnly, X-Frame-Options: DENY
  • check --deploy sans avertissement ; secrets en variables d'environnement

Accès et robustesse

  • @login_required + décorateurs de rôle ; LoginRequiredMixin + PermissionRequiredMixin pour la gestion des comptes
  • Un groupe Django par rôle avec ses permissions (mis à jour à chaque migrate)
  • Pages 400, 403, 404, 500 personnalisées ; IA, e-mail, SMS dans des try/except qui journalisent
  • Journal des connexions (traçabilité)

Intégration propre

  • Client unique (patients/ia_client.py) : clé en variable d'environnement, délai max 6 s, cache, quota par compte
  • Garde-fous : anonymisation, liste blanche, citation mot pour mot, consentement du patient
  • L'IA ne décide jamais seule : règles et médecin gardent la main

Performance et asynchronisme

  • Temps mesurés : médiane 423 ms, p95 1,9 s par note (Groq)
  • Celery + Redis : analyse du dossier (2 appels, jusqu'à 12 s) en arrière-plan, indicateur de chargement puis résultat ; e-mails en tâche de fond ; relecture IA reprogrammée si l'IA est en panne
  • Sans IA ou en panne : message explicite, les règles continuent

5 · UX / UI 1 point

Même charte sur toutes les pages (thème sombre contrasté, composants communs), responsive : menu latéral sur ordinateur, barre d'onglets en bas sur mobile ; menus identiques pour un même rôle dans tous les modules ; parcours guidés (étapes, confirmations avant suppression, messages de succès et d'erreur).
