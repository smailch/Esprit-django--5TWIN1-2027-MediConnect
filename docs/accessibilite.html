Rapport d'accessibilité

MediConnect · module Gestion patient · 25/10/2026 · référentiel : WCAG 2.1 niveau AA

1. Ce qui est en place

Critère de la grilleCe qui est fait
Structure sémantiqueChaque page a un seul <main>, des <nav> nommés (aria-label), un <header> et un <footer> (ajouté sur toutes les pages), un seul h1 et une hiérarchie de titres sans saut. lang="fr" et titre de page unique.
ARIA et textes alternatifsLes icônes décoratives sont masquées aux lecteurs d'écran (aria-hidden). Aucun bouton ni lien sans nom. Les champs sont liés à leur aide et à leurs erreurs (aria-describedby, aria-invalid), les erreurs sont annoncées (role="alert"), les messages ont role="status", la page courante est signalée (aria-current), les jauges ont role="progressbar".
Contraste et lisibilitéToutes les combinaisons de couleurs de l'interface respectent le rapport 4,5:1 (minimum mesuré : 6.30:1), voir le tableau ci-dessous. L'information n'est jamais portée par la couleur seule : chaque niveau d'urgence ou de gravité est écrit en toutes lettres. Les champs précisent leur sens au navigateur (autocomplete).
Navigation au clavierLien d'évitement « Aller au contenu principal » sur chaque page, focus visible sur tous les liens, boutons, champs et choix (contour de 2 px), aucun tabindex positif, animations désactivées si le visiteur le demande (prefers-reduced-motion), formulaires utilisables sans souris. Les liens du menu de l'accueil pointent tous vers une cible existante.

3. Comment le vérifier

  • Tests automatiques : python manage.py test core (classes ContrastesTests, StructureHtmlTests, PagesAccessiblesTests, ChampsDeFormulaireTests). Si une couleur devient trop pâle, si une icône perd son aria-hidden ou si le pied de page disparaît, un test échoue.
  • Audit des pages : python manage.py audit_accessibilite --patient <identifiant> --admin <identifiant> affiche les contrastes puis contrôle la structure de chaque page rendue (pages publiques, espace patient, back-office). Dernier résultat : 20 pages vérifiées, 0 défaut, 0 contraste insuffisant.
  • Audit navigateur : dans Chrome, ouvrir une page, touche F12, onglet Lighthouse, catégorie Accessibility, bouton Analyze page load.

4. Limites, sans les cacher

  • L'audit intégré au projet est un contrôle rapide, pas un audit complet : il ne remplace pas Lighthouse ni axe, qui doivent être lancés dans le navigateur pour la preuve devant le jury.
  • Le parcours au clavier a été vérifié par la structure et les styles de focus, pas par une session complète avec un lecteur d'écran réel (NVDA, VoiceOver).
  • L'interface est en thème sombre uniquement. Le texte peut être agrandi sans casser la mise en page, mais le zoom à 200 % n'a pas été mesuré page par page.
  • La page d'accueil est la plus riche en animations ; elles s'arrêtent si le système demande de réduire les animations.
